## C. 프레임워크 예외 처리 (404/405/415 -> 500) (해소)
[증상] 존재하지 않는 URI, 허용되지 않은 HTTP Method, 지원하지 않는 Content-Type 요청이 처리되지 않은 예외로 분류돼
   500(COMMON_001)에 ERROR 로그+스택 트레이스로 나감.
[조사] COMMON_003(404)/COMMON_004(405)은 API_Response_Rule §5.2와 ErrorCode에 이미 정의돼 있으나 던지는 곳이 없었음.
   415는 정의된 코드 없음 -> 새 결정. 선택지(COMMON_009 신설/COMMON_002 재사용/500 유지)를 제시하고 A(COMMON_009 신설) 승인.
   406(HttpMediaTypeNotAcceptableException)은 이번 범위에서 제외(API가 항상 JSON만 응답).
[구현] GlobalExceptionHandler: NoResourceFoundException/NoHandlerFoundException -> COMMON_003, HttpRequestMethodNotSupportedException
   -> COMMON_004, HttpMediaTypeNotSupportedException -> COMMON_009. WARN(event=HTTP_REQUEST_REJECTED, code만), 스택 트레이스 없음,
   응답 메시지/로그에 요청 URI/Method/미디어 타입 원문 미포함. NoHandlerFoundException은 정적 리소스 매핑이 꺼진 설정에서
   같은 상황에 던져지므로 함께 404로 묶음(요청 범위에 명시되지 않은 소소한 추가).
[테스트] 신규 FrameworkExceptionHandlerTest 10건. 핸들러 없이 먼저 실행해 6건 실패(404 x2, 405, 415, 로그 x2) 확인 후 구현하여 통과.
   전체 스위트 264건 통과(기존 254 + 10).
[실환경 curl(bootRun)] 인증O: 존재하지 않는 URL -> 404 COMMON_003, GET /ai/summary -> 405 COMMON_004,
   POST text/plain -> 415 COMMON_009. 인증X: 존재하지 않는 URL/허용 안 된 메서드 모두 401 AUTH_001 유지.
   잘못된 JSON은 여전히 400 COMMON_002. 서버 로그에 HTTP_REQUEST_REJECTED WARN 3줄(코드만, 스택 없음).
   참고: GET /anomalies/questions는 type 파라미터가 필수(문서 §3.9)라 파라미터 없이는 400 COMMON_002, type 지정 시 200 ANOMALY_003.
