# Git 작업 규칙
>해당파일 경로 .claude/rules/git.md
> Git 작업 시 반드시 준수해야 하는 실행 규칙이다.
> 브랜치 전략, Commit, Pull Request 및 Merge의 상세 운영 기준은
> `docs/development/git_strategy.md`를 따른다.

## 작업 전
- 작업 전 반드시 `git status`로 현재 브랜치와 작업 상태를 확인한다.
- 현재 브랜치를 확인하지 않은 상태에서 파일을 수정하거나 Git 작업을 수행하지 않는다.
- 기존 변경사항과 Untracked 파일을 확인한다.
- 사용자가 작성한 변경사항이 있는 경우 임의로 수정하거나 삭제하지 않는다.

## 변경사항 보호
- 기존 변경사항을 임의로 되돌리지 않는다.
- 사용자의 작업물을 덮어쓰지 않는다.
- 다른 브랜치의 작업물을 임의로 삭제하거나 변경하지 않는다.
- `git reset --hard`, `git checkout --`, `git restore` 등을 사용하여 기존 변경사항을 삭제하지 않는다.
- 변경사항 삭제가 필요한 경우 반드시 사용자에게 확인한다.

## Commit
- 사용자의 명시적인 요청 없이 Commit을 생성하지 않는다.
- Commit 전 변경 파일과 변경 내용을 확인한다.
- 하나의 Commit에는 관련된 변경사항만 포함한다.
- 다른 목적의 변경사항을 임의로 하나의 Commit에 포함하지 않는다.
- Commit 메시지는 프로젝트의 Commit 규칙을 따른다 (상세 규칙: `docs/development/git_strategy.md` §3).

## Branch
- 기능 개발은 `feature/*` 브랜치에서 수행한다.
- `main`, `dev`, `test` 브랜치에서 직접 기능 개발하지 않는다.
- 작업 전 현재 브랜치가 작업 목적에 적절한지 확인한다.
- 브랜치 생성, 전환 또는 삭제가 필요한 경우 현재 작업 상태를 먼저 확인한다.
- 기존 브랜치를 임의로 삭제하지 않는다.

## Pull Request / Merge
- Pull Request 생성 및 Merge는 사용자의 명시적인 요청 없이 수행하지 않는다.
- 변경사항을 Merge하기 전에 대상 브랜치와 현재 브랜치를 확인한다.
- 테스트되지 않은 변경사항을 임의로 `dev` 또는 `main`에 Merge하지 않는다.
- 충돌 발생 시 기존 변경사항을 임의로 삭제하거나 덮어쓰지 않는다.

## Remote
- Remote 설정을 임의로 변경하거나 삭제하지 않는다.
- 원격 브랜치를 임의로 삭제하지 않는다.
- 사용자의 명시적인 요청 없이 `push`하지 않는다.
- `main`, `dev`, `test`에 `force push`하지 않는다.
- `force push`가 필요한 상황에서는 실행 전에 사용자에게 확인한다.

## 작업 후
- Git 작업 후 `git status`로 최종 상태를 확인한다.
- 변경된 파일과 브랜치 상태를 확인한다.
- Push, Merge 또는 Branch 변경 후 결과를 확인한다.
- 작업 결과와 예상하지 못한 변경사항이 발생한 경우 사용자에게 알린다.
